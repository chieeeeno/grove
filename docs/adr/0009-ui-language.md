# ADR-0009: UI 言語は M0 / M1 では日本語のみとする

**日付**: 2026-04-07
**ステータス**: 確定

## 背景

Grove の UI（ボタン、ラベル、メッセージ、ダイアログ等）の表示言語を決める必要がある。
i18n（多言語対応）を最初から組み込むかどうかは、開発スピードと将来の拡張性のトレードオフがある。

## 検討した選択肢

- **A**: 日本語のみ（ハードコード、i18n フレームワーク無し）
- **B**: 日本語デフォルト + 将来 i18n 対応の余地を残す（M0 はハードコード、将来書き換え）
- **C**: 最初から i18n フレームワーク導入（react-i18next 等）

## 決定

**A: M0 / M1 では日本語のみ**

i18n / 英語対応は M2 配布フェーズで「世の中の反応を見て」から判断する。

## 理由

- 開発者本人が日本語話者であり、自分用フェーズ（M0）では日本語の方が作業効率が高い
- M1 の β 配布も知人（日本語話者）が対象であり、日本語のみで困らない
- i18n フレームワーク（react-i18next 等）の導入は M0 段階ではオーバースペック
- UI コピーを「英語キー → 日本語テキスト」に書く作業を省略でき、開発速度が上がる
- 将来 i18n が必要になった場合でも、コードベースが大きくなる前に書き換え可能（個人開発の規模なら問題にならない）

## 却下した選択肢の理由

- **C（最初から i18n）**: M0 段階で必要性がない。実装コストとライブラリ依存が増えるだけ
- **B（i18n の余地を残す）**: 「余地を残す」のために特別な書き方をするコストが、実際に i18n 化する時の書き換えコストとほぼ同じ。意味がない

## 将来 i18n を検討する条件

以下のいずれかが満たされたタイミングで再検討する:

- M2 配布フェーズで日本語話者以外からの利用要望が出た
- GitHub Issue 等で「英語版がほしい」というフィードバックが複数寄せられた
- 海外の開発者コミュニティ（Reddit、Hacker News 等）で取り上げられる兆候があった

i18n 化する場合は react-i18next を第一候補とする（React エコシステムでの定番）。
