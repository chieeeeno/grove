# ADR-0011: worktree カードの変更ファイル数表示は合計値のみとする

**日付**: 2026-04-07
**ステータス**: 確定

## 背景

worktree カードに表示する「変更ファイル数」の表示形式を決める。
小さな決定だが、検討した選択肢を残しておくことで将来の機能追加のヒントになるため記録する。

## 検討した選択肢

- **A**: `git status --porcelain` の行数を数字だけで表示（例: `5 changes`）
- **B**: 種別を分けて表示（modified / added / deleted / untracked を個別カウント、例: `M:3 A:1 ?:2`）
- **C**: アイコン + 種別（視覚的に区別）

## 決定

**A: 合計値のみ（数字だけ）**

## 理由

- カードに細かい情報を載せると視認性が落ちる
- M0 の目的は「変更があるかないか・どれくらいあるか」をひと目で把握すること
- 種別の詳細が必要なら VS Code を開いて Source Control パネルで確認する方が自然
- 設計書の「カードは最小限」の方針と揃う
- 実装が最もシンプル（`git status --porcelain | wc -l` 相当）

## 却下した選択肢の理由

- **B（種別ごと表示）**: カード上の情報密度が上がりすぎる。詳細表示はカード外（詳細パネルや VS Code）に任せる方が役割分担として正しい
- **C（アイコン + 種別）**: 同上。カードのレイアウトも複雑化する

## 将来の機能追加候補

却下した B / C は完全に否定するものではなく、将来の機能追加候補として記録しておく:

- **詳細パネル（Detail Panel）での種別表示** — カードはシンプルに保ちつつ、カードを選択した時に開く詳細パネル内で B / C 相当の情報を表示する設計が考えられる。これは設計書の Phase 2 以降の Detail Panel 設計と整合する
- **設定で表示形式を切り替え** — 「カード上で種別まで見たい」というユーザー要望が出た場合、設定オプションとして A/B を切り替え可能にする
- **ホバー時のツールチップ** — カードホバー時に種別ごとの内訳をツールチップ表示する軽量な拡張案
