# ADR-0010: ahead/behind 表示は M0 では実装しない（将来追加候補）

**日付**: 2026-04-07
**ステータス**: 確定

## 背景

設計書では worktree カードに「ahead/behind」（リモートブランチとのコミット差分）を表示する想定があった。
M0 スコープに含めるかを判断する。

## 検討した選択肢

- **A**: M0 で実装する（カードに表示）
- **B**: M0 では実装せず、M1 以降で追加候補とする
- **C**: そもそも実装しない

## 決定

**B: M0 では実装しない。M1 以降で必要性を再評価して追加検討する**

## 理由

### M0 で外す理由
- ahead/behind を取得するにはリモートとの差分計算が必要で、正確に出すには `git fetch` が前提となる
- 自動リフレッシュ時に毎回 fetch するとネットワーク負荷・パフォーマンス劣化が大きい
- 「PR 出す前に最新と差分確認したい」用途なら VS Code 内（GitLens 等）で見る方が自然
- M0 の優先度（自分が grove-app の worktree を管理できる）に対して必須ではない

### 機能自体は否定しない（C ではない）理由
- worktree がリモートとどれだけズレているかは、PR を出す前のチェックや、長期間放置された worktree の発見に有用
- 他の Git GUI ツールでは標準的な機能であり、配布フェーズではユーザーが期待する可能性が高い

## 却下した選択肢の理由

- **A（M0 で実装）**: 計算コストとパフォーマンス課題があり、優先度が低い割に実装が重い
- **C（そもそも実装しない）**: 将来的に価値のある機能であり、永久に外す決定をするのは早すぎる

## 将来追加する際の検討事項

実装する際は以下を考慮する:

1. **fetch のタイミング** — 自動リフレッシュに含めると重いので、手動リフレッシュ専用 / バックグラウンド間欠 fetch / カード選択時のみ等を検討
2. **fetch 失敗時の表示** — ネットワーク無し / 認証エラー時にカードがエラーまみれにならないようにする
3. **キャッシュ戦略** — 直近の fetch 結果をキャッシュして表示し、バックグラウンドで更新するパターンが現実的
4. **表示形式** — 「↑3 ↓2」のようなコンパクト表記
