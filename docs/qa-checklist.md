# Grove M0 QA テストケース

> M0（自分用 α）リリース前の動作確認用テストケース。
> 各テストは「前提条件 → 操作 → 期待値」の形式で記述。
>
> **記法:**
> - **TC-X.Y.Z**: テストケース ID
> - **Given**: 前提条件（テスト前に用意するデータ・状態）
> - **When**: ユーザーが行う操作
> - **Then**: 期待される結果

---

## 共通の前提条件

### 設定ファイルの保存場所

Grove は `tauri-plugin-store` を使用しており、設定ファイルは macOS の標準的な
アプリデータディレクトリに保存される：

```
~/Library/Application Support/io.github.chieeeeno.grove/grove_config.json
```

このファイルには以下が JSON 形式で保存されている:
- `repositories`: 登録済みリポジトリ一覧
- `worktree_labels`: worktree ラベル（worktree 絶対パスをキー、ADR-0008）
- `app_config`: アプリ設定（自動更新間隔等）

**便利なシェル変数:**
```bash
GROVE_CONFIG="$HOME/Library/Application Support/io.github.chieeeeno.grove/grove_config.json"
```

QA 中の設定リセット例:
```bash
# 設定を初期化
rm "$GROVE_CONFIG"

# 設定を破損させる（TC-1.1.3 用）
echo '{ "repositories": [' > "$GROVE_CONFIG"

# 読み取り権限を外す（TC-1.1.4 用）
chmod 000 "$GROVE_CONFIG"

# 書き込み権限を外す（TC-8.2.3 用）
chmod 444 "$GROVE_CONFIG"

# 復元
chmod 644 "$GROVE_CONFIG"
```

ウィンドウサイズ・位置は `tauri-plugin-window-state` が別ファイルに保存:
```
~/Library/Application Support/io.github.chieeeeno.grove/.window-state.json
```

### 準備データ（fixture リポジトリ）

以下の準備データを `~/qa-fixtures/` などに用意しておくと便利：

| 名前 | 内容 | 作成例 |
|------|------|--------|
| `clean-repo` | 初期コミットのみの git リポジトリ（変更なし） | `git init && touch a && git add a && git commit -m init` |
| `dirty-repo` | 未コミット変更が3ファイルあるリポジトリ | clean-repo に `touch b c d` を追加 |
| `multi-wt-repo` | サブ worktree が3つあるリポジトリ | `git worktree add ../wt-1 -b feat-1` 等を3回 |
| `large-repo` | worktree が10個以上ある巨大リポジトリ | for ループで `git worktree add` |
| `non-git-dir` | git 管理されていない普通のディレクトリ | `mkdir non-git` |
| `bare-repo` | bare リポジトリ | `git init --bare bare.git` |
| `jp-path-repo` | パスに日本語を含むリポジトリ | `mkdir ~/qa/日本語フォルダ && cd $_ && git init` |

## 1. 起動・初期化

### TC-1.1.1: 初回起動（設定ファイルなし）

**Given:**
- 設定ファイルが存在しない（事前に削除: `rm "$GROVE_CONFIG"`）
- アプリは未起動

**When:**
1. Grove アプリを起動する

**Then:**
- アプリが3秒以内に起動する
- ウィンドウサイズはデフォルト（1280×800）で表示される
- サイドバーに「リポジトリがありません」が表示される
- メインエリアに「リポジトリを選択してください」が表示される
- エラーダイアログが出ない
- 設定ファイルが新規作成される

---

### TC-1.1.2: 既存設定からの起動

**Given:**
- 設定ファイルに2件のリポジトリが登録済み（`clean-repo`, `multi-wt-repo`）
- いずれかのリポジトリにラベルが設定済み
- 自動更新間隔が 10秒 に設定済み
- アプリは終了状態

**When:**
1. Grove アプリを起動する

**Then:**
- リポジトリ一覧（2件）がサイドバーに復元される
- 最初のリポジトリ（`clean-repo`）が自動選択される
- worktree カードが即座に表示される
- 設定済みラベルが反映される
- 設定ダイアログを開くと自動更新間隔が「10秒」になっている
- ウィンドウサイズ・位置が前回終了時と同じ

---

### TC-1.2.1: preflight チェック（code コマンドあり）

**Given:**
- ターミナルで `which code` が成功する状態
- 任意のリポジトリが登録済み

**When:**
1. アプリを起動する

**Then:**
- 黄色の警告バナーが表示されない
- worktree カードの「VS Code」ボタンが有効（cursor: pointer、明るい青）

---

### TC-1.2.2: preflight チェック（code コマンドなし）

**Given:**
- ターミナルで `which code` が失敗する状態（PATH を一時的に外す等）
- 任意のリポジトリが登録済み

**When:**
1. アプリを起動する

**Then:**
- アプリ上部に黄色の警告バナーが表示される
- バナーに「code コマンドが見つかりません。VS Code で「Shell Command: Install 'code' command in PATH」を実行してください。」と表示される
- 全カードの「VS Code」ボタンが disabled（cursor: not-allowed、半透明）
- VS Code ボタンにホバーするとツールチップ「code コマンドが必要です」表示

---

### TC-1.1.3: 異常系 - 設定ファイル破損

**Given:**
- 設定ファイルに不正な JSON を書き込む:
  ```bash
  echo '{ "repositories": [' > "$GROVE_CONFIG"
  ```

**When:**
1. アプリを起動する

**Then:**
- アプリがクラッシュしない
- 「リポジトリがありません」状態で起動する（フォールバック）
- コンソールにエラーログが出る
- 新規追加で正常状態に復旧できる

---

### TC-1.1.4: 異常系 - 設定ファイル読み取り権限なし

**Given:**
- 設定ファイルのパーミッションを読めない状態にする:
  ```bash
  chmod 000 "$GROVE_CONFIG"
  ```
- テスト後は `chmod 644 "$GROVE_CONFIG"` で復元

**When:**
1. アプリを起動する

**Then:**
- アプリがクラッシュしない
- 「リポジトリがありません」状態で起動する
- コンソールにエラーログが出る

---

### TC-1.2.3: preflight 警告バナーを閉じる

**Given:**
- TC-1.2.2 の状態（警告バナー表示中）

**When:**
1. バナー右側の × ボタンをクリックする

**Then:**
- バナーが非表示になる
- VS Code ボタンの disabled 状態は維持される（バナーを閉じても根本原因は変わらないため）

## 2. リポジトリ管理

### TC-2.1.1: リポジトリ追加（正常系）

**Given:**
- アプリ起動済み・リポジトリ未登録
- `clean-repo` が存在する

**When:**
1. サイドバー下部の「+ リポジトリを追加」ボタンをクリック
2. ディレクトリ選択ダイアログで `clean-repo` を選択
3. 「Open」をクリック

**Then:**
- サイドバーに `clean-repo` が追加される
- 追加したリポジトリが自動選択される（ハイライト表示）
- メインエリアにヘッダー（リポジトリ名 + パス）が表示される
- worktree 一覧が即座に表示される
- サイドバーのバッジ数値が worktree 数（main worktree のみなら「1」）と一致する
- 設定ファイルに保存される（再起動後も残る）

**Then:**
- サイドバーに2件並ぶ

- バッジ数値が4（main + サブ3つ）と表示される

## 5. worktree 削除（§11.6）

### TC-5.1.1: 削除ダイアログ表示

**Given:**

**When:**
1. カードの「Remove」ボタンをクリック

**Then:**
- 半透明オーバーレイの上にダイアログが表示される
- 警告アイコン（赤い三角）+ 「worktree を削除しますか？」タイトル

- worktree 名と絶対パスが表示される
- **未コミット警告は表示されない**（クリーンなため）
- 「ブランチも一緒に削除する」チェックボックス（OFF 状態）+ ブランチ名
