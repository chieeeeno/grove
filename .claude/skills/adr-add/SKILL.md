# adr-add

Grove リポジトリ向けの ADR 追加 skill。`docs/adr/` 配下に整然と並ぶ
`NNNN-<slug>.md` 形式（4 桁ゼロパディング、kebab-case slug、太字メタ情報
`**日付**` / `**ステータス**` + 日本語節「背景 / 検討した選択肢 / 決定 / 理由」
の 4 節構成）の運用を維持するため、採番ミスとテンプレ揺れを機械的に防ぐ。

参照:

- `docs/adr/0014-auto-review-skill.md` — 既存 ADR の節構成・スタイルの正
- `.claude/skills/adr-add/template.md` — 本 skill が流し込むテンプレート

## 起動トリガー

- ユーザーが `/adr-add <slug>` で明示起動した場合のみ実行する
- `disable-model-invocation: true` のため Claude が自発的に呼び出すことはない

## 入力

- 引数 1 個: slug（例: `ahead-behind-display`、`commit-graph-view` 等）
  - 半角スペース・全角スペースは `-` に変換
  - 大文字は小文字化
  - 連続する `-` は 1 個に圧縮
  - 先頭末尾の `-` は除去
- 引数が無い場合: ユーザーに slug を要求して中断（先走って仮の slug を当てない）

## 手順

1. **次番号の採番**
   - `docs/adr/` 内のファイル名から、先頭 4 桁が数字のものを抽出
   - 最大番号を取得し、`+1` を 4 桁ゼロパディングした文字列を `NNNN` とする
   - 例: 既存最大 `0014` → 次は `0015`
   - `_template.md` のような数字以外で始まるファイルは無視する

2. **slug 正規化**
   - 上記入力ルールに従い slug を整形
   - 整形後の slug が空文字になる場合はエラー終了し、ユーザーに正しい slug を要求

3. **タイトル候補の生成（仮）**
   - slug の `-` を半角スペースに戻し、各単語の頭文字を大文字化したものを
     `{Title}` プレースホルダの仮値として使う
   - 例: `ahead-behind-display` → `Ahead Behind Display`
   - ユーザーが本タイトル（日本語可）を指定したい場合は後から手で書き換える前提

4. **テンプレート流し込み**
   - `.claude/skills/adr-add/template.md` を読み取る
   - 以下のプレースホルダを置換:
     - `{NNNN}` → 採番した 4 桁番号
     - `{Title}` → 上記 3 で生成した仮タイトル
     - `{YYYY-MM-DD}` → 実行日（ローカルタイムゾーン）
   - 出力先: `docs/adr/<NNNN>-<slug>.md`
   - 既に同名ファイルが存在する場合は **上書きしない** で、その旨をユーザーに通知して中断

5. **結果報告**
   - 生成したファイルの絶対パスをユーザーに 1 行で返す
   - 続けて中身を編集したい場合はユーザーが明示的に依頼する想定

## 出力

- 成功時: 生成されたファイルの絶対パス（例:
  `/Users/.../grove-app/docs/adr/0015-ahead-behind-display.md`）
- 失敗時:
  - slug 不正: 「slug を指定してください」など短いエラーメッセージ
  - 同名ファイル既存: 「既に <path> が存在します」
  - 採番不能（`docs/adr/` が無い等）: 環境エラーを示すメッセージ

## 注意事項

- ADR の **本文**（背景・検討した選択肢・決定・理由の中身）は書かない。
  テンプレートをそのまま入れて返すだけ。中身はユーザーが書くか、後で別途
  Claude に依頼する。
- ADR のステータス遷移（草案 → 確定 / 棄却 等）の運用は本 skill の範囲外。
  生成時点では `草案` 固定（既存 ADR は確定後に「確定」へ書き換える運用）。
- M1 以降で ADR の節構成や運用が変わった場合は `template.md` のみ更新すれば skill
  本体は変えなくて済むよう、テンプレ依存の責任分離を維持する。
